# 网吧老板模拟器

《网吧老板模拟器》是一款使用微信小游戏原生 JavaScript 与 Canvas 2D 开发的轻量经营管理游戏。玩家通过装修、设备、员工、营销和财务决策，将小网吧逐步经营为大型电竞馆。

当前版本仅为第一阶段基础项目：提供可运行的管理界面、静态网吧平面图、页面切换和带版本号的本地存档，不包含完整经营结算。

## 目录结构

```text
game.js / game.json              小游戏入口与运行配置
project.config.json              微信开发者工具项目配置
js/core/                         生命周期、状态、存档、输入等基础模块
js/data/                         默认存档和静态业务配置
js/systems/                      经营系统边界（第一阶段为轻量占位）
js/scenes/                       主场景及六个管理页面
js/ui/                           Canvas UI 组件
js/map/                          静态网格与装修预览渲染
assets/                          后续图片资源分类目录
```

## 运行方式

1. 打开微信开发者工具，选择“小游戏”。
2. 导入本目录作为项目目录。
3. 无 AppID 调试时可使用测试号；`project.config.json` 默认使用 `touristappid`。
4. 编译后以横屏进入“概览”页，可点击左侧六个菜单切换页面。
5. 首次启动会创建默认本地存档，之后启动会读取并兼容补齐缺失字段。

## 架构原则

- 使用 CommonJS 模块，入口文件只负责创建和启动 `Game`。
- `GameState` 是核心经营状态的唯一持有者，页面和系统不各自保存业务状态。
- 页面负责展示，业务系统负责计算，配置数据与逻辑分离。
- `InputManager` 统一接收触摸事件，交互区域与绘制区域使用同一布局数据。
- Canvas 按设备像素比绘制，并使用安全区域计算顶部与底部边距。
- 存档包含 `saveVersion`，通过 `SaveManager` 的迁移入口支持未来版本升级。
- 当前静态界面按需重绘，不进行无意义的逐帧对象遍历。
- 界面以横屏经营数据面板为目标，当前像素风家具由 Canvas 绘制；`AssetManager` 和分类资源目录为后续贴图替换预留入口。

## 明确禁止

本项目禁止加入可移动顾客或员工、人物寻路、人物碰撞、自动避让、角色进出路线及角色行为动画。顾客和员工只能作为经营统计数据存在。地图只用于静态装修展示，后续开发也必须遵守这一边界。

## 第二阶段：装修系统 MVP

装修系统只编辑家具数据，不引入人物、通道、寻路或物理碰撞。家具配置集中在 `js/data/furnitureCatalog.js`，正式存档中的家具实例只保存 `id/type/gridX/gridY/rotation`。装修页使用草稿数据，只有点击“保存方案”才会提交到 `GameState` 并写入本地存档；取消装修会丢弃草稿，不修改正式现金和正式布局。

网格占用只校验两件事：家具不能超出地图，家具之间不能重叠。这个校验不得扩展成人物通行、可走区域或路线系统。
